## Notes

- **B was released before A was installed (accepted).** B's version PR (#10) was merged, and `v0.1.1` tagged, on 2026-11-09, before step 1. Step 2 therefore checks that an unpromoted B is not delivered by an update, but not the order "A installed, then B released". The owner accepted this change of sequence on 2026-11-09 (staging plan, "Deviation (2026-11-09)", review 75).
- **Coverage exception: no checks at B after the in-place update (owner-accepted).** After the update to B (E.2) still rewriting and the data check were not run, and after the rollback to A (E.3) they were not run either. The update itself is shown: both hosts installed `f8589d5…`. The A checks were run after E.4 instead, labelled in the transcript, while both hosts were still at A (E.4 only showed that the pinned install stays at A). Rewriting on B was then shown after the return to `release` (E.5), which is a fresh install, not the in-place update; it does not fill that gap. So the behaviour of the hosts at B after an in-place update, and the data check at that point, were **not observed**. Each data check confirms that the step 1 rows and `config.json` bytes are present at that later checkpoint; intermediate states were not independently checked. The owner accepted this exception on 2026-11-12. It closes the procedural gate; it is not an observed pass. An unqualified full-runbook result would need that behaviour shown in a separately authorized drill.
- **Data survives marketplace removal.** The rollback and the return each run `claude plugin marketplace remove context-economy`, which printed "The removal also deletes their saved options, secrets and data where it can." The gateway's data under `~/.claude/context-economy/` was kept each time: the data check passed after both.
- **Step 1's override check most likely ran outside the clone (inferred).** It also printed `.claude/settings.json: CE_RTK_BIN absent`, a path relative to the folder it runs from, so a settings file existed there. No working directory was recorded. The clone has no such file now (checked on 2026-11-12, and a new check there prints no such line), and the later checks in the clone do not print it; so that check most likely ran from the home folder, where the path is `~/.claude/settings.json` again. This is an inference: the step 1 check did not demonstrate an inspection of the launch folder's project settings at that time, and the later checks prove only their own checkpoints. `CE_RTK_BIN` was absent in every settings file it checked; the hosts were then started in the clone.
- **Claude Code auto mode.** On each still-rewriting check the first rewritten Bash call was refused by auto mode, because a hook changed the input after its review; Claude Code then ran the rewritten `'/Users/drill/.local/opt/rtk-0.47.0/rtk' git status`. Each check therefore adds a `rewrite=applied`, `is_error=true` row and then a `rewrite=none` row to `gateway-ledger`. This is the known limit recorded for `0.1.0`.
- **Pi shows the command as typed** (`$ git status`). The rewrite shows in RTK's short output (`* main...origin/main`) and in Pi's ledger row, `rewrite=applied`. After the return to `release`, Pi also showed `0.1.1`'s changelog entry.
- **Part A's Claude Code session** was not kept on screen. Its calls were read back from the session file afterwards (the `node -e` command in step 1), showing the refused call, then the rewritten one.
- **RTK install.** The README's RTK block, saved unchanged as `~/run-install.sh`, printed only the macOS default-shell notice when run with `bash` and was then run with `zsh`, which printed `rtk 0.47.0` and the path. A later re-run with `bash -x` into a temporary home installed and verified the same release with exit 0; the first `bash` run's silence is not explained by the script.
- **Set-up, first clean check (b).** The first run of the account check in `drill` used commands written for the `e1b` account (`/Users/e1b/...`) and listed that account's folders. It was re-run with the `drill` account's own paths, and passed. In the first lines of the set-up transcript the owner removed the home folder prefix, so `~/.claude` shows as `/.claude`.
- **Claude Code updated itself** from 2.1.319 (set-up) to 2.1.322. Pi offered 1.5.2 throughout; it stayed at 1.5.0.
- **Promotions.** `promoted-v0.1.0` was created by run `42732062034` (its Promote step logged `release moved (new) -> 29840b1…`; the run then shows as cancelled after that step completed), and `promoted-v0.1.1` by run `42924484972` (`release moved 29840b1… -> f8589d5…`). Both tags name `context-economy-release[bot]` as tagger.
